# CAL-002 — Introduce a provider-neutral calendar domain

Status: shipped shared domain and local persistence foundation.

## Before change

Example: `CalendarTask` was the only calendar-shaped record, so completion, project ownership, provider identity, recurrence, and external event conflict semantics had no separate home.

## After change

Calendar events, links, external calendars, and connections are separate normalized records in `calendarDomain.ts` and `CalendarStore`. Tasks can be converted to local event projections, and links declare field ownership without changing task completion semantics. `CalendarStore` commits a single `calendar/state.json` aggregate with `writeFileAtomically`, then refreshes the existing collection files as compatibility mirrors; old vaults without the aggregate still read those collection files. Existing task storage remains compatible.

## Verification

`tests/calendarDomain.test.ts` covers all-day/timed normalization, links, recurrence validation, task projection, aggregate-vs-mirror reads, legacy collection fallback, and credential rejection. The service is registered behind calendar IPC channels.

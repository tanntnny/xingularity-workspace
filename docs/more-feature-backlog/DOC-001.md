# DOC-001 — Keep product, data, and feature documentation generated from decisions

Status: shipped documentation index and per-feature records.

## Before change

Example: the backlog described proposed work, while route docs and storage notes could disagree about hidden pages and legacy task paths; there was no one-file-per-feature implementation record.

## After change

`featureRegistry.ts` gives every backlog ID one status/priority/summary, `docs/more-feature-backlog/README.md` indexes all 27 records, and each feature record documents a concrete before example, after behavior, and verification evidence. Partial work is labeled instead of being presented as complete.

## Verification

All backlog IDs have a corresponding Markdown record, and the registry validation helper checks missing, duplicate, and unknown IDs.

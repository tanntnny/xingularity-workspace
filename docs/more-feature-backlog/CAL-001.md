# CAL-001 — Reconcile reminder lifecycles and make notifications actionable

Status: experimental reminder lifecycle foundation.

## Before change

Example: editing, completing, or deleting a task could leave a previously scheduled timeout active, and a notification only focused a window rather than carrying a task/date destination.

## After change

`ReminderService` computes a desired reminder set, cancels stale or changed timeout handles, suppresses duplicate identities, handles a bounded missed-reminder window, and ignores completed/disabled reminders. Runtime vault transitions stop inactive schedules and retain fired identities per vault scope. Notification clicks carry a path-free calendar target containing task ID, selected date, and view through main/preload IPC; the renderer selects the date, navigates to Calendar, and opens the task without receiving filesystem paths.

## Verification

`tests/reminderService.test.ts` covers reconciliation, stale handles, duplicate suppression, invalid dates, and click targets. Typecheck covers the end-to-end shared/preload/renderer contract.
